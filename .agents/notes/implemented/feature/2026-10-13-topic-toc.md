# Agent Note: 话题正文目录与标题跳转

Status: implemented

## Problem

话题正文中的 Markdown 标题需要目录入口和章节跳转，但普通帖子不应凭空生成目录。正文里的 HTML 表格也必须保留结构，普通引用与可跳转的来源引用需要有不同的视觉表达。

## Decision

主帖正文只有在首个有效元素包含 `data-theme-toc="true"` 且存在 `h2` / `h3` 标题时才生成目录。目录标题从主帖正文注册稳定锚点，回复、引用、签名和预览不参与；按钮沿用回到顶部宿主的液态玻璃位置，目录项点击后滚动并关闭弹窗。

HTML `table` 解析为带表头、行分隔线和内联内容的 `ArticleBlock.Table`，避免被当成代码块。普通 `blockquote` 在正文首行保留大引号和首行缩进；带 `source` 的 Discourse 来源引用是可跳原帖卡片，不显示装饰引号，也不增加首行空位。

## Alternatives considered

- 只滚动到主帖顶部：改动较小，但长帖内的章节仍可能位于屏幕下方，不能满足章节跳转。
- 把所有回复标题合并到主题目录：与网页只对主题正文生成目录的行为不一致，会让普通讨论主题错误出现入口。
- 将表格转成文本代码块：实现简单，但会丢失表格语义和单元格布局。
- 所有引用统一添加大引号：来源引用已有作者、折叠和跳原帖语义，额外引号会遮挡来源卡片正文。

## Consequences

目录入口只对网页标记的主题出现，避免普通主题误显示；锚点注册依赖对应帖子组合完成，远距离跳转需要等待目标锚点。表格单元格复用内联 Markdown 渲染，支持链接和富文本，但复杂的跨行跨列布局暂未建模。引用视觉规则按来源区分，普通引用的首行会为引号预留约两字宽度。
