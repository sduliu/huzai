# Agent Note: 楼层选择器关闭、连续拖动与动画稳定性

Status: implemented

## Problem

楼层内联选择器展开后始终显示确认图标，未修改楼层也会执行跳转。楼层少时，拖动过程被父层的整楼值回写，液态镜片呈台阶移动；展开和收回由多个独立可见性动画驱动，末尾移除两侧按钮时会发生宽度跳变。输入法打开时测试截图还可能看到多个 Compose 根节点。

## Decision

展开时保存起始楼层。有效目标与起始楼层相同时显示关闭图标，点击只收起选择器并隐藏键盘，不发跳转；目标改变后显示确认图标，点击沿原跳转流程定位。改回起始楼层即时恢复关闭图标，非法输入和跳转进行中保持禁用。

展开和收回使用一个 280ms 的过渡进度协调左右按钮透明度、外移、占位和中央控件宽度。中央编辑器按展开后的宽度测量，由父层裁切揭露，避免轨道宽度逐帧变化重建拖动状态；编辑器在动画期间位于索引按钮之上，静止时保留原有液态外沿和无障碍动作。

液态滑块在本地保留 0..1 连续视觉位置，拖动直接更新镜片和填充条，只把取整值用于楼层文本与跳转。拖动期间忽略父层的整数回声，松手、轨道点击和手动输入通过交互修订号重新对齐目标楼层。共享 `DampedDragAnimation` 的手势键绑定具体实例，避免范围变化后继续调用旧动画实例。

输入法场景的截图使用 `UiAutomation.takeScreenshot()`，因为 IME 会创建独立的 Compose 根节点；产品断言仍验证关闭动作、输入法收回和零跳转。

## Alternatives considered

- 增加弹簧刚度或缩短动画时间：改动少，但无法恢复取整丢失的连续位置，也不能消除轨道测量变化引发的状态重建。
- 用 Material Slider 替换现有控件：可复用成熟状态，但会丢失项目要求的 Backdrop 液态材质，因此保留并修复现有控件。
- 只请求更高刷新率：能增加显示机会，却不能修复整数台阶和动画终点几何变化；先修正状态与布局契约。

## Consequences

楼层数字仍是整楼语义，镜片和填充条在楼层之间连续移动，松手后会对齐所选楼层。布局动画增加了一个自定义测量层，但避免了终点突变和液态拖动状态重建。专项和关联测试覆盖了当前 RMX2202；没有 OnePlus 13 设备，无法替代该机的厂商高刷新率验收。
