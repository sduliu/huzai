# Agent Note: 批X13 比赛详情页球员卡数据行截断修复

Status: implemented

## Problem

批X7 有条件通过后唯一欠账：球员卡数据行（intro 官方成品串直渲，「19分 5板 9助 2断 3失误 5犯规」六项）尾部被截成「5犯…」，「犯规」末项不可见。官方同场球员卡整串完整显示。

## Root cause

纯宽度不足，非数据问题：`BasketballRatingRow` 内左列文本区 = 屏宽(360dp) − 列表内边距24 − 卡内边距24 − 头像56 − 两处间距22 − 右列（星70/计数~62 取宽者≈70）≈ **164dp**；而六项串 @12sp ≈175dp、七项串（「47分 4板 4助 2断 2帽 4失误 2犯规」）≈205dp → maxLines=1 + Ellipsis 尾部截断。intro 是官方成品串不可拆项改串。

## Decision

四处收宽让位，不改卡结构（56dp 头像/蓝大分/原始计数/灰星/引言块/分享 icon 全保留）：

- 数据行字号 12→11sp（官方该行本就是次级灰字，小幅降号换整串）
- 头像→左列间距 12→8dp、左列→右列间距 10→6dp
- 灰星 14→12dp ×5（右列宽 70→~62dp；灰星色与「不随分填充」语义不变）

净效果：左列文本区 164→~182dp。阈值口径（360dp 屏）：≤7 项数据串全显（六项 ~161dp / 七项 ~175dp）；8 项及以上极端组合仍 Ellipsis 兜底。

## Alternatives considered

- `maxLines=2` 换行显示：官方为单行整串，折行破坏卡高度节奏，弃。
- 数据行移出左列跨整卡宽（~248dp 全能放）：官方截图证据未落盘无法确认数据行是否伸到右列下方，保守不动结构。
- 字号降到 10sp 换更多宽度：与官方视觉字号差距变大，11sp 已覆盖 ≤7 项，够用即停。
- 拆 intro 串重排/缩写项（如「篮板」→「板」）：违反「官方成品串直渲」决策且 intro 不可信拆，禁。
